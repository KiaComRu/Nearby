# Архитектура и план развития

## Браузерный режим — 12 октября 2026

Добавлен независимый транспорт в `browser/`: два HTTPS-клиента соединяются через WebRTC DataChannel, сервер PHP служит только для кратковременного обмена параметрами соединения. Файлы идут напрямую, частями по 16 КиБ, с подтверждением после записи и проверкой SHA-256 каждой части. QR-библиотека собрана локально; внешнего QR-сервиса, STUN и TURN нет. Для начала соединения нужен интернет и доступная общая локальная сеть. Подтверждаются устройство и каждый файл.

Этот режим не использует HTTP API Windows-приложения и не требует его установки. Существующий EXE 0.2.0 продолжает использовать локальный Node.js-сервер. Браузерный режим — отдельная бета с ограничениями сохранения и фоновой работы; подробности: [BROWSER-MODE.md](BROWSER-MODE.md). Ниже сохранён план развития нативных приложений.

## Обновление: устанавливаемая Windows-версия 0.2

Пользователь выбрал начать с Windows без тяжёлых SDK; пока доступен только этот Windows-ПК. Создана WinForms/WebView2-оболочка с встроенным Node.js и сборка NSIS-установщика для текущего пользователя. Она переиспользует текущий HTTP-прототип. Общий переход на Flutter, описанный ниже как первоначальная гипотеза, не начинался.

Для следующей общей версии предпочтительным кандидатом стал [Tauri 2](https://v2.tauri.app/start/prerequisites/): документация указывает поддержку macOS Catalina 10.15 и мобильных целей. Сетевое ядро нужно перенести с Node.js на Rust, прежде чем появятся самостоятельные приложения Android/iOS. Совместимость Catalina всё ещё требует проверки настоящей release-сборки на Intel Mac. На текущем ПК нет Rust/C++ Build Tools/Android SDK, свободно менее 2 ГиБ; пользователь согласовал сначала лёгкую Windows-сборку. Подробности — [INSTALL-WINDOWS.md](INSTALL-WINDOWS.md).

## Цель

Отдельные приложения для Windows 10/11, macOS 10.15+, iOS и Android, передающие файлы напрямую между любыми двумя устройствами в доступной локальной сети. Без регистрации, интернета и централизованного сервера. Рабочее имя — Nearby, перед публикацией нужно проверить доступность названия.

Первый согласованный набор: подключение по адресу или QR-коду, выбор файлов, явное подтверждение приёма, прогресс. Автопоиск, папки и возобновление — следующие этапы.

## Что уже реализовано

Браузерный прототип на Node.js, проверяющий передачу компьютер ↔ другое устройство. Сервер хранит временные подключения в памяти и файлы на диске. Передача не загружает файл целиком в память. Веб-интерфейс использует стандартный выбор файлов и XHR для прогресса отправки; скачивание делегируется браузеру. QR создаётся локальной библиотекой `qrcode`; запросов к внешним QR-сервисам нет.

Этот сервер не является окончательным общим ядром для мобильных приложений: Node.js на телефонах не требуется и не встраивается. Прототип — исполняемая проверка сценария; окончательный транспорт нужно версионировать отдельно.

## Выбор стека для нативной версии

Предварительный выбор — Flutter/Dart для общего интерфейса и сетевого ядра. На каждом устройстве приложение сможет выступать отправителем и получателем; одинаковый транспорт работает поверх TCP/TLS. Для локального поиска — Bonjour/mDNS с платформенными реализациями через плагины. Для файлов — системный picker, потоковый доступ и системный экспорт/сохранение.

**macOS 10.15 — обязательная проверка до фиксации стека.** Актуальная [матрица Flutter 3.47](https://docs.flutter.dev/reference/supported-platforms) начинается с macOS 12 и iOS 15. В [Flutter 3.35](https://docs.flutter.dev/release/release-notes/release-notes-3.35.0) нижняя граница macOS была 10.15, iOS — 13. Выбор 3.35 как кандидата не означает, что современные плагины или требования магазинов с ним совместимы.

Порядок выбора:

1. Сделать минимальный compatibility spike на закреплённом патч-релизе Flutter 3.35: окно, выбор файла, сервер TLS, запись потока.
2. Запустить release-сборку на реальном Intel Mac с Catalina 10.15. Проверить все плагины и архитектуру x64. Сборочная машина может требовать более новую ОС, чем целевой Mac.
3. Проверить сборки актуальными Apple-инструментами и требования распространения iOS. Версии iOS/Android окончательно определить после проверки toolchain; ориентир для обсуждения — iOS 15+, Android 7/API 24+.
4. Если единая ветка не проходит проверку: использовать актуальный Flutter для Windows/iOS/Android/новых Mac и отдельный AppKit-клиент для Catalina с тем же протоколом. Это дороже в поддержке, зато сохраняет заявленную цель 10.15 без обещаний неподдерживаемой конфигурации.

Flutter SDK, Visual Studio C++ workload, Android SDK и Xcode в проект не устанавливались. Готовых native runners, APK, IPA, EXE и DMG сейчас нет. Сборки iOS/macOS требуют доступа к Mac и Xcode; Windows-машина не подтверждает их работоспособность.

## Транспорт нативной версии

- HTTPS/TLS с локальной идентичностью устройства и проверяемым отпечатком ключа. QR содержит адрес, версию протокола, одноразовый pairing token и fingerprint. Не отключать проверку сертификата глобально.
- Сначала обмен манифестом: имена, размеры и идентификаторы файлов. Только после согласия получателя — выдача ограниченных токенов передачи.
- Отправка чанками, ограниченное число параллельных потоков, backpressure, тайм-ауты и отмена. Размеры и границы проверяет получатель.
- Запись во временный файл, проверка SHA-256, затем атомарное переименование. Проверять свободное место с учётом всех активных передач.
- Возобновление по подтверждённому смещению/чанкам; хранение состояния в SQLite. Не допускать повторного использования токенов для другого манифеста.
- Имена и пути из сети всегда считать недоверенными; защита от traversal, symlink, коллизий и Windows reserved names обязательна.
- Прямое чтение исходного файла на отправителе, без промежуточной копии, которую сейчас делает браузерный прототип при раздаче.

## Особенности платформ

| Платформа | Интеграции и проверки |
| --- | --- |
| Windows 10/11 | Подписанные EXE/MSI или MSIX, системный выбор папки, частный профиль брандмауэра, tray, ARM64 отдельно |
| macOS 10.15+ | Catalina x64 отдельно; Intel/Apple Silicon для поддерживающих их ОС, sandbox entitlements сети/файлов, подпись и notarization |
| iOS | Разрешение локальной сети, системный Documents picker, share extension отдельным этапом, экспорт полученных файлов |
| Android | Storage Access Framework, системный выбор/сохранение, разрешения локальной сети по target SDK, foreground service для поддерживаемых фоновых передач |

На iOS нельзя обещать бесконечно работающий сервер или любую передачу после закрытия приложения. В первом нативном выпуске — явный режим «держать открытым во время передачи». Фоновые сценарии проектировать отдельно в пределах разрешённых системой механизмов.

В соответствии с [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) локальный доступ требует корректного описания `NSLocalNetworkUsageDescription`; для Bonjour нужно объявление сервисов. Проверять запуск и выдачу разрешения на физическом устройстве, а не только в симуляторе.

## Этапы и критерии готовности

1. **Прототип, текущий этап:** PIN/QR, компьютер ↔ браузер, согласие и прогресс, потоковая передача, интеграционные тесты. Проверить на реальных телефонах; не выдавать localhost-тесты за проверку четырёх ОС.
2. **Проверка совместимости:** Catalina, выбор стека/версий, устройства iOS/Android, подпись тестовых сборок. Результат — подтверждённая таблица минимальных ОС.
3. **Нативный MVP:** любые два устройства, TLS/pairing, выбор и сохранение, отмена, хеширование, история. Подготовить установочные пакеты.
4. **Удобство и надёжность:** автопоиск, папки, возобновление, ограниченный фон, системное «Поделиться», сохранённые доверенные устройства.
5. **Выпуск:** подписи, магазины/распространение, инструкции, проверка безопасности и измерение скорости.

Матрица приёмки: Windows ↔ Mac, Windows ↔ iPhone, Windows ↔ Android, Mac ↔ iPhone, Mac ↔ Android, iPhone ↔ Android. Для каждой пары — оба направления, отказ, отмена, сон/обрыв, повторное соединение, Unicode, одинаковые имена, пустой файл, 1 МиБ/1 ГиБ/10 ГиБ при доступном месте. Скорость сравнить с сетевым baseline в той же сети; цифры до измерений не обещать.
