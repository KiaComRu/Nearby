# Nearby в браузере — бета 0.3.0

Адрес: https://nearby.kiacom.ru/web/. Установка на компьютер или телефон не требуется. В Windows 0.3.0 кнопка «Открыть интернет-режим» открывает этот сайт в системном браузере; полученные таким способом файлы сохраняются средствами браузера.

## Подключение

1. На первом устройстве выберите режим. «В одной сети» подходит для доступной общей локальной сети. «Через интернет» подходит для разных Wi-Fi и мобильной сети; оба устройства должны иметь доступ к HTTPS-сайту Nearby.
2. Нажмите «Создать подключение» и отправьте второму устройству полную ссылку либо покажите QR-код.
3. На втором устройстве откройте приглашение и нажмите «Подключиться».
4. На первом подтвердите имя получателя. Выберите файл на любом устройстве; получатель подтверждает приём.
5. Оставляйте обе вкладки открытыми, не блокируйте телефон до завершения. После приёма нажмите «Сохранить файл», если браузер не предложил выбрать место заранее.

Приглашение одноразовое: 15 минут в локальном режиме, до 2 часов в интернет-режиме при активности. В комнате два устройства. После закрытия или потери сессии создайте новое приглашение; докачки и восстановления после перезагрузки нет. Имя устройства можно изменить; оно хранится в localStorage и передаётся серверу для подтверждения получателя.

## Транспорт и приватность

В локальном браузерном режиме WebRTC DataChannel передаёт данные напрямую с DTLS. PHP обменивает только описания соединения и ICE-кандидаты. STUN/TURN не используется. Изоляция Wi-Fi, VPN и настройки локального доступа могут препятствовать соединению; тогда создайте новое приглашение в режиме «Через интернет».

В интернет-режиме устройства делают исходящие HTTPS-запросы к Nearby: открывать порты роутера не нужно. Сервер временно буферизует зашифрованные части, пока второе устройство их забирает. Содержимое, имена файлов и управляющие сообщения шифруются на устройствах AES-256-GCM. Для комнаты и каждого направления из случайного 256-битного секрета выводится отдельный ключ HKDF-SHA-256; номер сообщения задаёт уникальный IV и проверяется при приёме. Ключ находится только во фрагменте приглашения после #, не отправляется в API и не сохраняется в localStorage. Приглашение не публикуйте: полный адрес даёт возможность присоединиться и расшифровать передачу. На принимающем устройстве фрагмент очищается из адресной строки.

Сервер видит IP, имена устройств, время, объём зашифрованного трафика и отчёт о числе/размере завершённых файлов. Приватный буфер содержит только шифротекст и служебные номера. Полученные части удаляются после подтверждения следующего запроса; при явном закрытии весь буфер очищается. Неполученные части становятся недоступны через 90 секунд; интернет-сессия без запросов устройства прекращается через 120 секунд. Просроченные файлы состояния физически удаляются при следующем запросе API, не чаще раза в минуту; без запросов они могут оставаться на диске до следующей очистки. Это временная пересылка, а не облачное хранение.

Код сайта и HTTPS-сервер остаются доверенными: шифрование не защищает от подменённого сайта или скомпрометированного устройства. Сервер не проверяет независимо факт сохранения файла; счётчик основан на отчёте клиента. Локальный HTTP-режим установленного Windows-приложения остаётся отдельным транспортом для доверенной сети.

## Размеры и сохранение

Интернет-режим: **до 100 МиБ на файл** на обоих устройствах. Бета ограничена 20 активными интернет-комнатами и общим суточным бюджетом 5 ГиБ шифротекста UTC; при исчерпании API сообщает об этом. Фактический сетевой трафик больше из-за кодирования и пересылки. Скорость зависит от обоих интернет-соединений и хостинга. Передача требует доступности сайта на обоих устройствах; блокировки сайта и отсутствие интернета исключают подключение.

В локальном браузерном режиме Chrome/Edge на ПК с разрешённой потоковой записью имеет программный предел 10 ГиБ; реальный такой объём ещё не проверен. На телефонах и без File System Access API — 100 МиБ на файл и суммарно в памяти вкладки. Сохраняйте полученные файлы и нажимайте «Убрать из памяти». Отказ браузера в выборе/открытии файла на ПК допускает обычное скачивание в пределах памяти; отмена пользователем отменяет приём. Ошибка начатой записи не переключает способ сохранения.

Каждая часть проверяется SHA-256 и подтверждается после записи. Локальные части — 16 КиБ; интернет-части — до 256 КиБ после согласования. Одновременно по одному файлу в каждом направлении, очередь выбранных файлов последовательная.

## Разработка и проверки

Нужны Node.js 22+, PHP 8.1+ с 64-битными целыми и современный браузер с Web Crypto.

```sh
npm ci
npm run build:web
php -S 127.0.0.1:8088 -t browser
npm run test:web
npx playwright install chromium
npm run test:browser
npm run test:internet
```

Для PHP можно задать PHP_PATH. NEARBY_WEB_URL меняет адрес WebRTC-проверки. Интернет-проверка сама запускает PHP с отдельным временным хранилищем: два браузерных контекста, WebRTC выключен, разрешён только адрес сайта. Проверяются обе стороны, SHA-256 файлов, отказ, пустой файл, лимит, отсутствие имён и ключа в запросах, счётчик и отключение. Она моделирует недоступность локального транспорта; проверка физических ПК/телефона в двух реальных сетях ещё требуется.

## Развёртывание

В публичную папку /web/ копируются index.html, styles.css, app.js, transfer.mjs, relay.mjs, api.php, relay.php, statistics.php, statistics.js, значки, .htaccess и vendor/. Apache должен отдавать .mjs как JavaScript. Нужен HTTPS; php -S предназначен только для разработки. Новые relay.php/relay.mjs и transfer.mjs загружайте до api.php/app.js.

Состояние храните вне public_html с правами 0700. Настройка NEARBY_WEB_STATE_DIR или config.private.php: массив с stateDirectory и необязательным relayDailyBytes. Конфигурация не входит в Git. По умолчанию отдельный системный temp; для счётчика нужен постоянный каталог. Буфер ограничен 1 МиБ шифротекста на направление комнаты; API проверяет роли, подтверждение, порядок, размеры, частоту и повторные кадры. Повтор потерянного ответа не увеличивает суточный бюджет. Неуспех передачи не должен обнулять статистику. Сохраняйте statistics.json/statistics.lock и секрет подписи статистики при публикации. Прокси и PHP должны допускать JSON до 768 КиБ.

## Общий счётчик передач

После полного приёма и закрытия потока получатель отправляет `record-transfer` с ID файла и его размером в байтах. Для буфера памяти это означает завершённый приём, а не подтверждение сохранения на диск. Отправитель не дублирует отчёт; API дополнительно исключает повторный подсчёт ID в одной комнате, включая повторы от другого участника. Отчёт требует ключ действующего подтверждённого подключения. Сбои статистики не прерывают передачу: клиент делает до трёх попыток, без постоянной очереди после закрытия вкладки.

Публичный POST `{ "action": "stats" }` к `api.php` возвращает только `files`, `bytes`, `startedAt`, `updatedAt`. Лендинг обновляет показатели раз в минуту, использует десятичные Б/КБ/МБ/ГБ/ТБ и раскрывает точный объём по нажатию. При сбое показывает недоступность, не нулевые значения. Windows 0.2.1 и локальный запуск из исходников пополняют тот же счётчик. Windows 0.2.0 и передачи до запуска статистики в итог не входят. См. [общую статистику](STATISTICS.md). Сервер доверяет отчёту клиента о завершении и не проверяет передаваемые напрямую байты независимо.

`statistics.json` и `statistics.lock` хранятся в том же приватном `stateDirectory`, что и комнаты. Для опубликованного сайта обязательно задайте постоянный каталог вне `public_html`: системный temp может очищаться. При обновлении сайта сохраняйте эти файлы; резервируйте JSON, удерживая `statistics.lock`, либо копируйте уже атомарно опубликованный JSON. Запись использует общую блокировку и атомарную замену JSON; повреждённое хранилище даёт 500, не обнуляется. Служебные ID для защиты от повторов удаляются при следующем отчёте после истечения комнаты; итоги остаются. До 1000 уникальных отчётов на комнату, до 10 ГиБ на файл и общий лимит запросов API. Имена и содержимое файлов в статистике не сохраняются; веб-сервер может вести собственные журналы запросов.
