# Устройства рядом — Nearby 0.4.0

Автопоиск доступен в установленном Windows-приложении и локальном Node.js-клиенте. Откройте Nearby на двух ПК в общей доступной IPv4-сети: в блоке «Компьютеры рядом» появится карточка второго компьютера с векторной иконкой, именем и IP. Нажмите «Подключиться»: для нового защищённого ПК откроется сверка строки на двух экранах, для сохранённого — защищённое подключение, для прежнего HTTP-клиента — ввод PIN. При нескольких адресах одного ПК раскройте «Другой сетевой адрес» в карточке. Обновление требуется на обоих ПК для автопоиска; ручное подключение к 0.2.2+ сохраняется.

## Что показывает диагностика

Кнопка «Проверить адрес» выполняет публичную проверку API Nearby без авторизации на другом ПК. PIN не нужен и попытки ввода PIN не расходуются.

- Nearby отвечает: можно ввести PIN и подключиться.
- Соединение с портом отклонено: проверьте, что приложение открыто и адрес актуален. Порт может измениться после перезапуска.
- Нет маршрута: проверьте адаптер, общую сеть и VPN.
- Нет ответа вовремя: проверьте адрес, разрешение входящих соединений для частной сети и изоляцию Wi-Fi.
- Несовместимое приложение: обновите Nearby или проверьте адрес.
- Адрес собственного ПК: выберите другое устройство.

Причина блокировки не определяется достоверно по одному тайм-ауту. Nearby не заявляет, что проверил настройки брандмауэра, и не отключает его. Если поиск недоступен, приложение продолжает работать по адресу/PIN. Для разных сетей используйте кнопку «Открыть веб-версию»; она сразу открывает отдельный HTTPS-режим через интернет в браузере.

## Поиск и приватность

Собственная реализация Nearby, без включения кода LocalSend или PairDrop. Протокол `nearby-discovery/1`, UDP 53318, группа 239.255.53.17, multicast TTL 1. Объявления идут через доступные частные IPv4-адаптеры примерно раз в 5 секунд. Сетевые подписки обновляются при смене адресов. Устройство исчезает после объявления о закрытии либо примерно через 20 секунд без сообщений. При ошибке сокета приложение повторяет запуск поиска; передача по адресу остаётся доступной.

В объявлениях находятся только случайный ID текущего запуска, условное имя вида «Windows · Эльбрус», версия и TCP-порт. Имя компьютера/пользователя из ОС не собирается. При перезапуске условное имя и ID могут измениться: это пока не постоянное сопряжение. PIN, токены, пути, имена и содержимое файлов в UDP не передаются. Метаданные поиска видны другим участникам локальной сети. Поиск можно отключить переменной `NEARBY_DISABLE_DISCOVERY=1` до запуска приложения.

Объявления не аутентифицированы и считаются подсказками. Адрес берётся из источника UDP, не из произвольного URL в сообщении; допускаются только поддерживаемые частные IPv4. API списка и проверки доступны только локальному владельцу с административным ключом. Обнаружение не подтверждает личность устройства, не создаёт сеанс и не разрешает приём файлов. При подключении проверяется совместимость API и требуется PIN; каждый входящий файл по-прежнему подтверждает получатель. Нынешний локальный файловый транспорт — HTTP в доверенной сети. Защищённое постоянное сопряжение относится к следующему этапу.

Ограничены размер объявления (1024 байта), частота обработки, число устройств (100), адресов на устройство (8) и частота ручных запросов поиска. Запрос проверки адреса не пересылает ключ владельца на другой ПК, не разрешает публичные адреса, служебный link-local 169.254.169.254, URL с паролем, произвольные пути и перенаправления.

Автопоиск не является сканированием подсетей. Некоторые роутеры, VPN и брандмауэры блокируют multicast; одинаковое имя Wi-Fi не гарантирует доступность. Обычная страница телефона не принимает UDP и не объявляет телефон в этом списке. Телефон подключается по QR/ссылке либо через интернет-режим.

## Проверки

`npm test` проверяет обработку недоверенных пакетов, ограничения, смену адаптеров, недоступность UDP, права API, отсутствие секретов и диагностику. `npm run test:discovery` проверяет настоящий UDP multicast двух независимых движков, выбор ПК, PIN, передачу с SHA-256, исчезновение устройства и мобильную ширину интерфейса. Для CI есть `NEARBY_TEST_DISCOVERY_IN_MEMORY=1`: транспорт объявлений моделируется, HTTP и браузер остаются настоящими; эта проверка не выдаётся за сетевой тест. Пределы проверки: два движка на одном ПК. Два физических ПК и конкретные роутеры/Windows Firewall ещё требуют проверки.

## Защищённое сопряжение в 0.5.0

Новые клиенты объявляют публичный отпечаток сертификата и TLS-порт. Кнопка «Подключиться» на карточке запускает сопряжение для нового ПК и защищённое подключение для сохранённого. Объявление остаётся недоверенным; первое подтверждение выполняется сравнением всей строки на двух экранах, последующие соединения проверяют сохранённый сертификат. Условное имя нового защищённого клиента сохраняется вместе с идентичностью. [Инструкция](TRUSTED-DEVICES.md).
