# Веб/PWA 0.6.4 — повторная передача на iPhone

После первого файла iPhone мог открыть просмотр или сохранение вместо страницы Nearby. Обработчик ухода со страницы закрывал канал и освобождал адреса принятых файлов. На отправителе следующий выбор файла становился недоступен либо передача ожидала подтверждения.

На iPhone и iPad приём остаётся автоматическим, но просмотр больше не запускается автоматически: файл появляется в «Принятых файлах». Чтобы открыть или сохранить его, нажмите иконку окна со стрелкой. Открытие использует отдельную вкладку. Перед закрытием Nearby сохраните нужные файлы: список хранится в памяти страницы, суммарно до 100 МиБ.

При переходе страницы в кеш истории браузера (`pagehide.persisted`) приложение сохраняет соединения и Blob-адреса для возврата. Настоящий уход со страницы по-прежнему освобождает ресурсы.

На Android и настольных браузерах автоматическое скачивание сохранено. Изменение находится на принимающем iPhone, поэтому работает с существующим отправителем Windows 0.6.2 без переустановки приложения на ПК. Обновите страницу Nearby на iPhone либо закройте и снова откройте PWA и создайте новое подключение.

## Проверка

`scripts/iphone-repeat-transfer-e2e.mjs` проверяет по четыре последовательных файла с одного веб-отправителя через HTTPS-релей и напрямую по WebRTC, а также из интерфейса Windows с настоящим движком и интернет-шлюзом. Проверяются SHA-256, одинаковые имена, пустой файл, открытие просмотра, возврат сохранённой страницы и обратная отправка через тот же сеанс.

Для HTTPS-сценариев используется Playwright WebKit с параметрами iPhone, для прямого WebRTC — Chromium с теми же параметрами. Переход iOS в системный просмотр моделируется при попытке автоматического скачивания: десктопный WebKit не содержит интерфейс загрузок физического iPhone. На прежнем коде проверка обнаружила автоматическую навигацию и закрытие сеанса; после исправления все сценарии прошли. Физический iPhone и установленная Windows-оболочка в этой проверке не использовались.
