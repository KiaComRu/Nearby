# Передача файлов между двумя ПК — Windows 0.5.0

Рекомендуемый способ: установите 0.5.0 на оба ПК, выполните [защищённое сопряжение](TRUSTED-DEVICES.md) и подключитесь через «Мои устройства». Ниже описан отдельный прежний HTTP/PIN-режим. Для автопоиска достаточно 0.4.0+ на обоих компьютерах. В блоке «Устройства рядом» выберите второй ПК и введите PIN с его экрана. Кнопка «Проверить адрес» помогает проверить доступность. [Поиск и диагностика](DISCOVERY.md). Ручной способ ниже работает с 0.2.2 или новее. Подключите их к одной доступной локальной сети — через Wi-Fi, Ethernet или их сочетание. Интернет для передачи файлов не нужен.

1. На первом ПК откройте Nearby и оставьте режим «Пригласить устройство».
2. Нажмите «Копировать» рядом со ссылкой приглашения. Если есть несколько адресов, выберите адрес адаптера общей сети. Это адрес вида http://192.168.1.10:порт, а не ссылка окна владельца 127.0.0.1.
3. На втором ПК откройте Nearby, нажмите «Подключиться к ПК» и вставьте ссылку. PIN из ссылки заполнится автоматически; его также можно ввести вручную. При желании измените имя второго ПК.
4. Нажмите «Подключиться к ПК».
5. Второй → первый: выберите файлы на втором ПК. На первом ПК нажмите «Принять». Файлы сохранятся в его «Загрузки → Nearby».
6. Первый → второй: добавьте файлы в раздачу на первом ПК. На втором нажмите «Скачать» и выберите файл назначения в диалоге Windows. По умолчанию предлагается папка «Загрузки → Nearby» второго ПК.
7. Чтобы завершить подключение, на втором ПК нажмите «Вернуться к своему подключению». Перезапуск приложения не требуется.

В режиме подключения кнопка «Открыть папку» открывает папку полученных файлов именно этого ПК. При обновлении страницы подключение восстанавливается из работающего локального движка. Если другой ПК закрыт или перезапущен, завершите текущее подключение и подключитесь заново с его новым адресом/PIN.

## Если связь не устанавливается

- Проверьте, что Nearby обновлён до 0.2.2 на обоих ПК и остаётся открытым.
- Используйте адрес из текущего окна первого ПК: после перезапуска порт и PIN могут измениться.
- При нескольких сетевых адаптерах выберите адрес общей сети; адрес виртуальной машины или другого VPN может быть недоступен второму ПК.
- Разрешите входящие подключения Nearby/его встроенного Node.js для доверенной частной сети в брандмауэре Windows. Не отключайте брандмауэр целиком.
- Гостевая сеть и изоляция Wi-Fi-клиентов на роутере могут запрещать связь между устройствами. Один SSID сам по себе не гарантирует доступность.

Транспорт Windows по-прежнему использует HTTP в доверенной локальной сети. Для разных сетей нажмите «Открыть интернет-режим»: он откроется в системном браузере и использует зашифрованную HTTPS-пересылку. Это отдельный транспорт. В браузере на втором ПК по-прежнему можно открыть локальную ссылку первого ПК без установки.

## Что исправлено

Ранее каждое установленное приложение открывало только свой локальный сервер, а переход к адресу другого ПК был запрещён Windows-оболочкой. Теперь локальный движок по явному адресу и PIN устанавливает гостевое подключение к другому Nearby и передаёт разрешённые API-запросы и файловые потоки. Окно остаётся на собственном loopback-адресе, поэтому доступ владельца и папка загрузок второго ПК сохраняются. Содержимое файлов не проходит через хостинг.

Ключ другого ПК хранится только в памяти локального движка; в браузер передаются публичные сведения о соединении. Подключаться могут только локальные владельцы приложения. Прокси не разрешает подтверждать чужие запросы, открывать чужую папку, управлять чужой раздачей или обращаться к произвольным URL. Ссылки скачивания одноразовые. Общий счётчик учитывает завершённую передачу на принимающем/раздающем движке один раз.

## Проверки и пределы

Автоматические тесты запускают два независимых движка с разными папками данных и двумя отдельными браузерными сеансами. Проверены двоичные данные и пустые файлы в обе стороны с SHA-256, отказ, неверный PIN, ограничения доступа, одноразовое скачивание, обновление страницы, переподключение и остановка другого движка. Эти проверки проходят на одном компьютере; два физических Windows-ПК и настройки конкретного роутера/брандмауэра требуют проверки пользователем.
