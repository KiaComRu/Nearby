# HTTP API прототипа 0.1

Все API-ответы, кроме SVG и скачивания, — JSON. Ошибка: `{ "error": "описание" }`. URL по умолчанию `http://<IPv4>:53317`. API не является стабильным контрактом нативной версии; перед её созданием добавить `/v1` и negotiation.

## Авторизация

`POST /api/join` с `{ "pin": "123456", "device": "Телефон" }` выдаёт `{ "token": "..." }` на 12 часов. Не более 8 попыток на IP за 5 минут. Успешные подключения тоже считаются попытками.

Все последующие API-запросы требуют `Authorization: Bearer <token>`, кроме одноразового скачивания. Ключ владельца печатается в консоли, разрешён только с loopback и передаётся тем же заголовком. В браузере ключ сохраняется только в `sessionStorage`. Ключ из URL-фрагмента удаляется из адресной строки после чтения.

`Origin`, если присутствует, должен совпадать с origin сервера. Host должен соответствовать одному из известных при запуске IPv4/loopback-адресов. Произвольные DNS-имена не поддерживаются.

## Состояние и QR

- `GET /api/state`: роль, доступные раздачи и свои запросы. Владелец получает все запросы, PIN, адреса сервера и абсолютный путь `receivedDirectory`. Удалённым клиентам пути хранения не раскрываются.
- `POST /api/received/open`: открыть фиксированную папку полученных файлов в Проводнике/Finder на серверном компьютере. Только локальный владелец. Путь или команда из запроса не принимаются.
- `GET /api/qr?ip=<IPv4>`: SVG с URL подключения и PIN во фрагменте. Только владелец. QR предоставляет право подключиться и не должен распространяться публично.

## Приём файла на компьютер

1. Клиент: `POST /api/offers` с `{ "name": "photo.jpg", "size": 123 }` → `201`, идентификатор и `pending`.
2. Владелец: `POST /api/offers/<id>` с `{ "action": "accept" }` или `reject`.
3. Клиент видит `accepted` через `/api/state`.
4. Клиент: `POST /api/offers/<id>/upload` с сырыми байтами, `Content-Type: application/octet-stream` и точным `Content-Length`. Потоковая передача с chunked encoding не принимается; браузер сам задаёт размер для File/Blob.
5. Сервер записывает временный `.part`, проверяет количество байт и переименовывает → `201`, `completed`. Повторная загрузка тем же запросом запрещена.

Состояния: `pending`, `accepted`, `uploading`, `completed`, `rejected`, `expired`, `failed`. Ожидание и разрешение истекают через 5 минут каждое. Запрос принадлежит только выданному сеансу. После ошибки создайте новый запрос. При обрыве полное сообщение об ошибке может не дойти по разорванному сокету; конечное состояние доступно через `/api/state`.

Имена ограничены 180 байтами UTF-8, запрещены разделители пути, управляющие символы, завершающие точки/пробелы и Windows reserved names. Предел одного файла — 100 ГиБ, не гарантия поддержки такого размера всеми браузерами. Сервер допускает до 3 одновременных записей и проверяет запас места; полноценного резервирования диска ещё нет.

## Раздача с компьютера

1. Владелец: `POST /api/shares?name=<encoded-name>&size=<bytes>` с сырыми байтами и `Content-Length` → `201`, `{ "id", "name", "size" }`.
2. Авторизованный клиент: `POST /api/shares/<id>/ticket` → `{ "url": "/api/shares/<id>/download?ticket=..." }`.
3. `GET` по выданному URL без заголовка авторизации возвращает attachment с `Content-Length` и UTF-8 именем. Ссылка действует 5 минут и на одно использование. Range/resume не поддерживается.
4. Владелец: `DELETE /api/shares/<id>` удаляет копию из раздачи. Исходный файл пользователя не меняется.

Копии в раздаче и полученные файлы сохраняются на диске. Список раздачи, токены и история пропадают при перезапуске. Клиенты с действующим PIN-сеансом имеют доступ ко всей текущей раздаче.

## Границы прототипа

HTTP без TLS; нет проверки хеша, pairing fingerprint, прямого мобильного сервера, устойчивой истории, докачки, автопоиска, отзыва конкретного устройства и квот общего объёма. Для публичного выпуска эти ограничения нужно устранить. Код API-тестов в `test/transfer.test.mjs` показывает минимальную последовательность работы.
