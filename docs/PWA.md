# Nearby как приложение на телефоне

Веб-версию https://nearby.kiacom.ru/web/ можно добавить на главный экран Android или iPhone/iPad и запускать отдельным окном. Дополнительный сервер, аккаунт, APK или подписка для этого не нужны.

## Android

1. Откройте веб-версию по HTTPS в Chrome или другом браузере с поддержкой установки веб-приложений.
2. Нажмите «Установить Nearby», если эта кнопка появилась. Появление кнопки контролирует браузер; иногда нужны посещение страницы и взаимодействие с ней.
3. Если кнопки нет, откройте меню браузера ⋮ → «Установить приложение» / «Добавить на главный экран». Название пункта зависит от браузера.
4. Запускайте Nearby через новый значок. Создайте подключение либо вставьте полное приглашение со второго устройства в поле приложения.

## iPhone и iPad

1. Откройте веб-версию в Safari.
2. Нажмите «Поделиться» → «На экран “Домой”».
3. Если Safari предлагает «Открывать как веб-приложение», включите этот переключатель. Подтвердите добавление.
4. Откройте Nearby через значок. Если приглашение открылось в отдельной вкладке браузера, скопируйте его полностью и вставьте в поле подключения внутри Nearby.

Подсказки установки показаны на странице и переведены на русский, английский, хинди, китайский и испанский. В установленном окне подсказка скрывается. PWA использует те же режимы передачи, подтверждения и ограничения размеров, что и обычная веб-версия; отдельного постоянного сопряжения телефонов этот этап не добавляет.

## Сеть, файлы и обновления

Для создания подключения нужен доступ к серверу Nearby. В одной сети передача использует WebRTC; в интернет-режиме — существующий зашифрованный HTTPS-транспорт. Во время передачи оставляйте приложение открытым и телефон разблокированным. PWA не добавляет фоновую передачу, автоматическую докачку или Wake Lock. После обрыва создайте новое подключение и отправьте файл заново.

При запуске без сети после первого успешного открытия появляется отдельный экран «Сейчас нет связи» с кнопкой повторной попытки. В PWA-кэш записаны только три публичных ресурса этого экрана. HTML рабочей сессии, файлы, приглашения, ключи и ответы PHP API сервис-воркер не кэширует. Для раздачи и API сохраняется обычное сетевое поведение; ключ шифрования остаётся только в приглашении/памяти открытой сессии.

Обновление service worker ожидает закрытия всех использующих его окон Nearby. Приложение не вызывает `skipWaiting`, `clients.claim` или автоматическую перезагрузку во время передачи. При готовом обновлении завершите передачу, сохраните принятые файлы, закройте все окна Nearby и откройте снова. Очистка ограничена собственными версиями офлайн-кэша Nearby в текущем scope.

Манифест имеет постоянные `id`, `start_url` и `scope` внутри `/web/`, без приглашений и секретов. Режим окна — `standalone`. Используются PNG 192/512 и отдельная maskable-иконка; iOS получает существующий apple-touch-icon. Все иконки получены из существующего SVG Nearby.

## Сборка и проверки

```sh
npm run build:web
npm run test:pwa
```

`build:web` генерирует `browser/sw.js` из шаблона с ревизией содержимого офлайн-экрана. PNG включены в исходники; для их повторного создания используйте `npm run build:pwa-icons` с установленным Chromium Playwright. В Apache нужны MIME `application/manifest+json` для `.webmanifest` и проверка обновления `sw.js` без долгого HTTP-кэширования; настройки включены в `browser/.htaccess`.

E2E проверяет Chromium installability, размеры иконок, scope `/web/`, обработку событий установки, офлайн/возврат к сети, отсутствие приватных данных в CacheStorage, настоящую зашифрованную передачу при ожидающем обновлении, последующую активацию и сохранение чужих кэшей. Флаг iOS standalone и события install prompt в тесте моделируются. Установка через настоящее системное меню Android/iOS требует проверки на физических телефонах.

Основания: [критерии установки Chrome](https://web.dev/articles/install-criteria), [инструкция Apple](https://support.apple.com/ru-ru/guide/iphone/iphea86e5236/ios), [жизненный цикл service worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API).
