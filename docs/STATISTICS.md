# Общая статистика Nearby

Один общий счётчик объединяет браузерные WebRTC- и интернет-передачи, Windows начиная с 0.2.1 и запуск локального приложения из исходников. Он показан на лендинге, в браузерной версии, в Windows и на подключённом к Windows телефоне. Отдельных приложений macOS/iOS/Android пока нет; эти устройства используют браузер.

## Количество использований

С версии Windows 0.5.1 и обновлённой веб-версии общий итог также содержит **количество использований**. Одно установленное соединение двух устройств — одно использование, даже если файлы ещё не отправлялись. Новое подключение тех же устройств учитывается снова. Сохранённое доверие, поиск устройств, открытие страницы, неудачный PIN, неподтверждённый запрос и служебные опросы не увеличивают итог.

Веб-клиент сообщает о готовности протокола передачи после подтверждения получателя. Оба устройства используют одну комнату: повторные отчёты, в том числе от второй стороны, учитываются один раз. Для следующего соединения создаётся новое приглашение/комната. Windows считает соединение на принимающем движке при первом успешном запросе состояния. Новый исходящий сеанс имеет случайный UUID; повторные запросы состояния сохраняют его. Это позволяет учитывать повторное подключение сохранённого TLS-устройства без двойного отчёта от обоих ПК. В локальном телефонном HTTP/PIN-сеансе идентификатор закреплён за новым входом по PIN.

Исторические подключения ранее не записывались. При первом обращении новый PHP-код добавляет `uses = 0` и отдельную дату `usesStartedAt`, сохраняя прежние `files`, `bytes`, `startedAt` и таблицу передач. Начало нового учёта показано рядом с метрикой; старые значения не выдумываются. Старые вкладки нужно обновить, Windows — обновить до 0.5.1. Предыдущие клиенты продолжают отправлять статистику файлов, но не сообщают об использовании.

Для локального подключения отправляются только случайный ID сеанса, время события и тип клиента, без размера, имени, адреса, сертификата или PIN. `record-local-usage` использует существующий краткоживущий подписанный ключ статистики и ту же атомарную очередь до 1000 событий/7 суток. Повторная отправка после отсутствия интернета или потери ответа сервера не увеличивает итог повторно. Соединение продолжает работать при ошибке статистики. Счётчик не является защитой от намеренно ложных отчётов авторизованного клиента.

API `stats` теперь возвращает `uses` и `usesStartedAt` вместе с прежними полями. Ошибка или отсутствие метрики в старом API показывается прочерком. Общий виджет и его подписи работают на пяти языках лендинга, в браузерной/PWA-версии и в установленном Windows-клиенте.

Проверки: `test/usage-statistics.test.mjs` проверяет миграцию, конкуренцию PHP, отчёты обеих сторон, повторные PIN/TLS-подключения и очередь после перезапуска. `npm run test:usage` проверяет настоящие веб- и локальные подключения, все пять главных страниц, мобильный/широкий экран и неизменность прежних файлов/байтов. Тесты используют отдельное хранилище, не публичные счётчики.

## Когда учитывается файл

- Браузер (WebRTC или интернет-режим): получатель проверил все части и завершил запись в файл либо буфер памяти. Сохранение из буфера на диск не подтверждается серверу.
- Телефон → Windows: файл полностью записан, проверен по длине и переименован из временного файла.
- Windows → телефон: HTTP-поток раздачи завершился без ошибки. Это подтверждает выдачу сервером, а не независимую проверку сохранения на устройстве.
- Добавление в раздачу, скачивание владельцем своей раздачи, отказ, оборванный поток и неполная загрузка не увеличивают итог. Повторное успешное скачивание другим устройством считается новой передачей.

Windows 0.2.0 и более старые сборки не сообщают статистику. Обновление до 0.2.1 устанавливается вручную. Старые передачи восстановить нельзя. Уже накопленные браузерные итоги сохраняются при включении Windows.

## Отчёты и очередь

Локальный Node.js-движок передаёт по HTTPS в https://nearby.kiacom.ru/web/api.php только случайный ID передачи, размер, время завершения в секундах и тип клиента (windows/local). Имена, пути, содержимое файлов, PIN и локальные ключи сопряжения в отчёты не входят. Веб-сервер может вести собственные журналы обращений.

При отсутствии интернета локальная передача продолжает работать. Файл statistics-outbox.json хранит до 1000 отчётов, не старше 7 суток, в папке данных программы; в Windows это %LOCALAPPDATA%\Nearby\Data. Очередь сохраняется атомарно и отправляется в фоне, при следующем запуске и затем раз в минуту. После закрытия приложения отчёты ждут следующего запуска. При переполнении очереди или ошибке её записи файл остаётся успешно переданным, но его отчёт может не попасть в итог. Повреждённая очередь не обнуляется автоматически. Неверное системное время может привести к отклонению отчёта.

Движок получает короткоживущий подписанный ключ через local-session и отправляет record-local-transfer. Встроенного общего секрета в EXE нет; ключ существует только в памяти. Это ограничение API, а не подтверждение подлинности клиента: сервер доверяет заявлениям клиента и не наблюдает сами локальные/WebRTC-файлы. Повторная отправка одного ID с тем же временем не увеличивает итог, в том числе после обновления ключа. Лимит локального файла — 100 ГиБ; ограничение WebRTC остаётся 10 ГиБ или 100 МиБ в зависимости от браузера.

## Сервер и хранение

PHP использует приватный постоянный stateDirectory вне public_html. statistics.json содержит общие files/bytes/startedAt/updatedAt и временные ID для защиты от повторов; statistics.lock защищает замену JSON. statistics-secret — постоянный случайный секрет подписи ключей. Не удаляйте эти файлы при обновлении; резервируйте их вне public_html. Истёкшие ID очищаются при последующих отчётах, итоги сохраняются. Старый формат statistics.json совместим; миграция или сброс не нужны.

Лимиты: 240 запросов в минуту с адреса, 10 созданий комнат/ключей в минуту, 1000 ID на браузерную комнату, 50 000 локальных ID на календарный UTC-день. Подпись ключа действует сутки; отчёт принимается до 7 суток после завершения и не более чем на минуту в будущем. PHP должен быть 64-битным.

Локальный интерфейс читает общий итог через GET /api/statistics: Node.js запрашивает публичный PHP action=stats и кеширует успешный ответ до минуты. Локальные токены и очередь в интерфейс не выдаются. Браузерный режим и лендинг читают тот же публичный итог напрямую. Ошибка статистики отображается прочерками, не нулём. Локальный счётчик и лендинг используют десятичные Б/КБ/МБ/ГБ/ТБ с шагом 1000; нажатие на объём раскрывает байты.

Для разработческих тестов createApp({statistics:false}) отключает отправку; statistics:{endpoint,fetchImpl,source} позволяет направить тесты на отдельное хранилище. NEARBY_DISABLE_STATISTICS=1 отключает её в Windows-движке. Автоматические тесты не добавляют данные в публичный итог.
