# LocalSend, PairDrop и AirDash: что применить в Nearby

Дата исследования: 13 октября 2026. Сравнение с Nearby 0.3.0. Изучены документация, лицензии и выбранные исходники; приложения конкурентов не запускались, измерения скорости и испытания на физических устройствах не проводились. Ниже отдельно обозначены обнаруженные решения и предложения для Nearby. Производственный код и хостинг в рамках исследования не изменялись.

**Основной вывод:** полезнее объединить автопоиск и защищённый локальный транспорт LocalSend, постоянное сопряжение и WebRTC с TURN из PairDrop, управление потоком и интеграцию с системой из AirDash. Текущую архитектуру Nearby можно развивать постепенно.

## LocalSend

**Автопоиск вместо ручного ввода адреса.** Протокол объявляет устройство через UDP multicast; передаются имя, порт, версия и fingerprint. Предусмотрен резервный поиск через HTTP. В текущем коде discovery поиск организован по этапам: объявление, проверка известных адресов избранных устройств, затем поиск в подсетях. Реализация учитывает перезапуск сетевого слушателя. [Спецификация](https://github.com/localsend/protocol/blob/62bd3406ec80d62f2ed46269cdc06c4dcc391083/README.md), [реализация discovery](https://github.com/localsend/localsend/blob/14f3a87426eedffaa9d87d011132eca5501abeb8/packages/localsend_isolates/lib/src/task/discovery/discovery.dart).

Предложение: показывать в установленном Nearby список «Устройства рядом» с кнопкой подключения. Сохранить адрес/PIN как резерв. Учитывать несколько адаптеров, смену Wi-Fi, VPN и Windows Firewall. Не сканировать бесконтрольно большие подсети. Обычный браузерный клиент не получает UDP discovery: список ему может отдавать локальный движок Windows, а телефон продолжит открывать QR/ссылку.

**HTTPS и идентичность устройства.** LocalSend хранит ключи, сертификат и его хеш. В проверенном отправителе HTTP-клиент привязан к fingerprint получателя для проверки TLS-соединения. Это полезный ориентир для текущего локального HTTP-транспорта Nearby. [Контекст безопасности](https://github.com/localsend/localsend/blob/14f3a87426eedffaa9d87d011132eca5501abeb8/app/lib/provider/security_provider.dart), [отправитель](https://github.com/localsend/localsend/blob/14f3a87426eedffaa9d87d011132eca5501abeb8/app/lib/provider/network/send_provider.dart).

Предложение: постоянная криптографическая идентичность ПК, подтверждение первого сопряжения, проверка сохранённого ключа при повторном подключении. Самоподписанный сертификат сам по себе не устанавливает доверие к незнакомому устройству. Для телефона в обычном браузере отдельно решить доверие к локальному HTTPS; не строить сценарий на отключении проверки сертификатов.

**Пакетное согласование файлов.** API сначала передаёт список и метаданные; получатель может принять весь набор, часть или отказаться. Для передачи выдаются сессия и файловые токены. Предложение: один экран «12 файлов, 850 МБ» с выбором файлов и общим прогрессом. Не заменять подтверждение простым фактом обнаружения устройства. [Upload API](https://github.com/localsend/protocol/blob/62bd3406ec80d62f2ed46269cdc06c4dcc391083/README.md#4-file-transfer-http-aka-upload-api).

Отдельная перспективная возможность — адаптер совместимости Nearby с LocalSend: обмен с уже установленными мобильными клиентами. Для этого потребуются полноценные API, TLS, discovery и тесты совместимости; одного совпадения порта или формата объявления недостаточно.

## PairDrop

**Постоянное сопряжение.** После кода/QR браузеры сохраняют общий секрет в IndexedDB и используют его для взаимного обнаружения при следующих запусках. Это избавляет от нового приглашения каждый раз. [Описание механизма](https://github.com/schlagmichdoch/PairDrop/blob/1b0c9c9d903c3cfc706df1303dc75c3b54d04c77/docs/technical-documentation.md#device-pairing), [хранилище](https://github.com/schlagmichdoch/PairDrop/blob/1b0c9c9d903c3cfc706df1303dc75c3b54d04c77/public/scripts/persistent-storage.js).

Предложение: «Мои устройства», переименование, индикатор присутствия, отзыв сопряжения. Секрет поиска и ключ файлового шифрования должны иметь разные роли. Нынешний ключ интернет-комнаты Nearby нельзя просто сохранить и повторно применять после перезапуска с обнулёнными номерами AES-GCM сообщений: новой сессии нужны новые ключи. Сохранённое сопряжение не должно автоматически разрешать любые входящие файлы.

**WebRTC, STUN и TURN.** PairDrop поддерживает заданные серверы ICE. Браузер ищет работающий прямой путь; при необходимости использует TURN для пересылки зашифрованного WebRTC-трафика. Самостоятельному размещению для надёжной работы в разных сетях нужен свой TURN либо соответствующий сервис. STUN не заменяет TURN. [Развёртывание](https://github.com/schlagmichdoch/PairDrop/blob/1b0c9c9d903c3cfc706df1303dc75c3b54d04c77/docs/host-your-own.md), [объяснение TURN от WebRTC](https://webrtc.org/getting-started/turn-server).

Предложение: единый сценарий подключения с выбором транспорта при установлении сессии: прямой WebRTC, затем TURN, затем уже имеющийся зашифрованный HTTPS-транспорт, если RTC недоступен. Показывать выбранный путь. Это не означает бесшовную смену транспорта посреди файла: её следует проектировать вместе с докачкой. Текущий PHP-хостинг можно оставить для сайта и API; TURN потребует отдельного сервера/услуги и бюджета трафика. Нельзя использовать чужие публичные TURN-учётные данные как инфраструктуру Nearby.

**Мобильный интерфейс.** У PairDrop есть PWA, приём через share target, выдача файлов через системное меню «Поделиться», пакетное скачивание, предварительный просмотр и предотвращение сна во время передачи. [README](https://github.com/schlagmichdoch/PairDrop/blob/1b0c9c9d903c3cfc706df1303dc75c3b54d04c77/README.md), [manifest](https://github.com/schlagmichdoch/PairDrop/blob/1b0c9c9d903c3cfc706df1303dc75c3b54d04c77/public/manifest.json).

Предложение: добавить установку Nearby как веб-приложения, отправку ссылок/текста, системное сохранение/обмен где доступно, общий прогресс набора и Wake Lock на время активной передачи. Wake Lock не гарантирует работу при закрытой или скрытой вкладке. PWA не обеспечивает одинаковую интеграцию с меню «Поделиться» на Android и iOS. [Ограничения Wake Lock](https://www.w3.org/TR/screen-wake-lock/).

**Что не переносить буквально.** Необязательный WebSocket fallback PairDrop, согласно документации, передаёт доступный серверу трафик. В Nearby следует сохранить прикладное шифрование резервного транспорта. Кроме того, FileDigester собирает файл в памяти, затем создаёт Blob; этот код не решает задачу больших файлов на телефоне. [Предупреждение о fallback](https://github.com/schlagmichdoch/PairDrop/blob/1b0c9c9d903c3cfc706df1303dc75c3b54d04c77/docs/host-your-own.md#websocket-fallback-for-vpn), [FileDigester](https://github.com/schlagmichdoch/PairDrop/blob/1b0c9c9d903c3cfc706df1303dc75c3b54d04c77/public/scripts/network.js).

## AirDash

**Ограниченное число частей в передаче одновременно.** DataSender держит до 10 сообщений без подтверждения и согласует размер WebRTC-сообщения. Получатель обрабатывает части по смещениям, пишет их во временный файл и отправляет подтверждение после записи. Это хороший образец управления потоком без ожидания каждого отдельного сетевого круга. [DataSender](https://github.com/simonbengtsson/airdash/blob/ef2f08691771f53e3fa7150d1f02e2d0835c694c/lib/transfer/data_sender.dart), [Receiver](https://github.com/simonbengtsson/airdash/blob/ef2f08691771f53e3fa7150d1f02e2d0835c694c/lib/transfer/data_receiver.dart).

В браузерном `FileLink` Nearby сейчас используется ожидание ACK после каждой части. При задержках сети и HTTPS polling это ограничивает скорость даже при хорошем канале. Предложение: согласуемое окно частей, подтверждение записанного смещения, ограничение буферов и измерение скорости. Начинать с малого окна: серверный буфер Nearby — 1 МиБ на направление, поэтому десять частей по 256 КиБ в него не поместятся. Даже четыре таких зашифрованных части превышают лимит из-за служебных данных. Число частей и их размер выбирать вместе; сохранить проверку SHA-256 и обработку отмены. Это предложение по коду, а не результат сравнительного замера скорости.

**Настройка TURN с ограниченным сроком действия.** Серверная часть AirDash предусматривает получение TURN credentials через API Cloudflare с TTL и обновление конфигурации по расписанию. Для Nearby полезен сам принцип серверного выпуска временного доступа, без выдачи клиенту основного API-секрета. Firebase или конкретный поставщик для этого не обязательны. Не переносить подробное логирование конфигураций и credentials. [Серверные функции](https://github.com/simonbengtsson/airdash/blob/ef2f08691771f53e3fa7150d1f02e2d0835c694c/functions/index.js).

**Интеграция с ОС и диагностика.** Есть обработчик входящих файлов из системного Share, проверка доступности получателя перед отправкой, отдельные ошибки соединения/передачи и попытка определить тип используемого ICE-пути. Предложение: «Отправить через Nearby» в Windows, системный Share в будущих мобильных приложениях, понятные причины отказа и экспорт локального диагностического отчёта без ключей, имён файлов и содержимого. [IntentReceiver](https://github.com/simonbengtsson/airdash/blob/ef2f08691771f53e3fa7150d1f02e2d0835c694c/lib/intent_receiver.dart), [Connector](https://github.com/simonbengtsson/airdash/blob/ef2f08691771f53e3fa7150d1f02e2d0835c694c/lib/transfer/connector.dart).

## Предлагаемый порядок работ

| Очередь | Изменение в Nearby | Что получает пользователь | Условия |
|---|---|---|---|
| 1 | Автопоиск установленных клиентов, проверка доступности и причины ошибок | Подключение выбором устройства, меньше ручного ввода и неясных сбоев | Windows/LAN; резервный адрес/PIN сохраняется |
| 2 | Защищённый локальный транспорт и «Мои устройства» | Повторное подключение к проверенному устройству | Первое сопряжение и хранение ключей; отдельный сценарий для браузера телефона |
| 3 | Ограниченное окно частей, скорость, оставшееся время, общий прогресс набора | Быстрее и понятнее передача через интернет | Проверка при задержке, потере ответов, медленном диске, отмене и двустороннем обмене |
| 4 | Автоматический выбор WebRTC/STUN/TURN с сохранением HTTPS-резерва | Один понятный сценарий для разных сетей | Отдельная TURN-инфраструктура; измерение трафика и стоимости |
| 5 | PWA, Wake Lock, текст/ссылки, системное Share | Меньше действий на телефоне | Проверки возможностей и ограничений каждого браузера |
| 6 | Большие файлы, докачка, папки, необязательная совместимость с LocalSend | Передача крупных наборов и работа с существующими мобильными клиентами | Потоковая запись, устойчивое состояние, проверка целостности и безопасные пути |

Пункты с разной сложностью можно выпускать отдельно. Простые улучшения интерфейса не требуют ожидания TURN. Повышать текущий интернет-лимит 100 МиБ на всех платформах одним изменением константы нельзя: нужны подходящий способ записи, проверка мобильной памяти, времени сессии и серверных квот.

Полную докачку после перезапуска устройства нельзя считать готовым заимствованием: в рассмотренных модулях не обнаружен завершённый механизм, который можно перенести в Nearby без отдельного проектирования. ACK, смещение части или повтор блока внутри живой сессии ещё не означают устойчивую докачку. Для Nearby нужны сохранённое подтверждённое смещение, идентификация исходного файла, проверка частичного файла и новая криптографическая сессия.

Перед выпуском транспортных изменений нужны физические проверки: два Windows-ПК в общей сети; Windows и Android/iPhone; Wi-Fi против мобильной сети; два разных роутера; VPN/изоляция клиентов; прерывание сети и медленный получатель. Автоматические браузерные контексты дополняют эти проверки.

- **LocalSend — Apache-2.0:** при переносе кода сохранять лицензию, необходимые уведомления и отмечать изменения. Заимствованный Apache-код не становится MIT автоматически. У спецификации в отдельном репозитории не следует предполагать ту же лицензию без её проверки. [LICENSE приложения](https://github.com/localsend/localsend/blob/14f3a87426eedffaa9d87d011132eca5501abeb8/LICENSE).
- **AirDash — MIT:** при переносе существенных фрагментов сохранять уведомление об авторских правах и лицензию. Dart-код потребует адаптации к Node.js/JavaScript/C# Nearby. [LICENSE](https://github.com/simonbengtsson/airdash/blob/ef2f08691771f53e3fa7150d1f02e2d0835c694c/LICENSE).
- **PairDrop — GPL-3.0:** прямое включение его кода требует выполнения условий GPL для соответствующего производного продукта. Для сохранения выбранной MIT-лицензии Nearby предлагается собственная реализация полезных подходов. Отдельные библиотеки PairDrop могут иметь другие лицензии, которые проверяются отдельно. [LICENSE](https://github.com/schlagmichdoch/PairDrop/blob/1b0c9c9d903c3cfc706df1303dc75c3b54d04c77/LICENSE).

Ни один сторонний модуль не подключён к Nearby по итогам этого исследования. Снимки выбранных файлов сохранены только в игнорируемой служебной папке `.build-tools/research` для воспроизводимого анализа.
