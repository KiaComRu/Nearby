# Nearby для Windows Server 2016

Отдельная сборка Nearby 0.5.2 для **Windows Server 2016 x64 с Desktop Experience**. Это обычное оконное приложение для вошедшего пользователя. Его можно запускать в интерактивной RDP-сессии. При закрытии окна или выходе из учётной записи движок останавливается; служба Windows и запуск без входа пользователя в эту сборку не входят.

## Установка

1. Запустите `Nearby-0.5.2-windows-server-2016-x64-setup.exe` в учётной записи, которая будет пользоваться Nearby.
2. Нужны .NET Framework **4.6.2 или новее** и **Microsoft Edge WebView2 Evergreen Runtime x64**. .NET 4.6.2 входит в Server 2016. WebView2 на сервере может отсутствовать: установите его с [официальной страницы Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/), затем откройте Nearby. Для сервера без интернета Microsoft предлагает Evergreen Standalone Installer. Системные компоненты Nearby автоматически не устанавливает.
3. Установка выполняется без повышения прав в `%LOCALAPPDATA%\Programs\Nearby`. Node.js уже включён. На рабочем столе и в меню «Пуск» появится ярлык.
4. Для связи с Windows-ПК установите на втором устройстве Nearby 0.5.0. Найдите его в «Устройства рядом», сверьте полную строку проверки на обоих экранах и подтвердите сопряжение. Далее используйте «Мои устройства». См. [защищённое сопряжение](TRUSTED-DEVICES.md).
5. Файлы сохраняются в системную папку «Загрузки → Nearby». Ключи и доверенные устройства находятся в `%LOCALAPPDATA%\Nearby\Data`, ключ защищён DPAPI текущего пользователя.

Сборка использует те же папки установки и данных, что и обычная Windows-версия. Закройте Nearby перед обновлением. Данные и полученные файлы сохраняются; одновременный запуск двух вариантов под одним пользователем запрещён. Установщик пока без цифровой подписи.

## Сеть на сервере

Разрешите входящие соединения `%LOCALAPPDATA%\Programs\Nearby\runtime\node.exe` в брандмауэре для нужного доверенного профиля сети. UDP 53318 нужен для поиска; HTTP и отдельный TLS TCP-порт выбираются при запуске. Правило только для одного старого TCP-порта не обеспечит повторный запуск и защищённое подключение. На доменном сервере действуют также политики администратора и правила сетевого оборудования. Nearby не изменяет брандмауэр или GPO автоматически.

Если multicast недоступен, используйте актуальный адрес из окна другого ПК и «Защищённое сопряжение по адресу». Не пробрасывайте порты Nearby в интернет. Для разных сетей доступен отдельный [браузерный интернет-режим](BROWSER-MODE.md); постоянное локальное сопряжение само по себе не соединяет разные сети. Телефонный локальный QR/PIN использует HTTP в доверенной сети.

## Отличия сборки

- Оболочка компилируется против **reference assemblies .NET Framework 4.6.2**, с `/nostdlib+`, а не против API установленного на сборочной машине 4.8.
- `Nearby.exe.config` и `TargetFrameworkAttribute` требуют 4.6.2. Обычная Windows-сборка продолжает использовать свой профиль 4.8.
- Установщик проверяет версию Windows, разрядность, .NET и отсутствие Server Core. Server Core оконной сборкой не поддерживается.
- Встроен Node.js 24 x64. Его [таблица платформ для используемой версии 24.13.0](https://github.com/nodejs/node/blob/v24.13.0/BUILDING.md#platform-list) включает Windows Server 2016. [Microsoft указывает поддержку Server 2016 в WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/).
- Защищённая передача использует TLS 1.3 встроенного Node.js/OpenSSL; она не требует включения TLS 1.3 в Windows Schannel.

## Сборка и проверка

На сборочной Windows x64 с Node.js 24 и системным компилятором .NET:

```powershell
npm ci
npm run build:server2016
node scripts/server2016-smoke.mjs
```

Официальные reference assemblies .NET 4.6.2 версии 1.0.3 скачиваются из NuGet с проверкой SHA-512 метаданных. Результаты: установщик в `artifacts/`, `artifacts/windows-server-2016-build.json` с SHA-256 и отдельная staging-папка `dist/windows-server-2016-x64`. Обычный EXE 0.5.0 не заменяется этой сборкой.

Автоматическая проверка запускает упакованный Node.js и движок, проверяет пользовательские папки, реальную DPAPI-защиту ключа, приём двоичного файла и корректную остановку. Она выполняется на текущей Windows сборочной машины. **Запуск оболочки, установка WebView2 и передача на настоящем Server 2016 ещё требуют проверки**; проверка библиотек и сборка не заменяют испытание на целевой ОС.

## Счётчик использований в 0.5.1

Каждое успешное подключение двух устройств, в том числе повторное, пополняет отдельный общий счётчик. Для точного учёта повторных TLS-сеансов обновите оба ПК до 0.5.1. Старые ключи доверия и полученные файлы сохраняются. Офлайн-отчёты отправляются позже; подробности — [STATISTICS.md](STATISTICS.md).

## Отправка из Проводника в 0.5.2

После установки выделите файлы и выберите «Отправить через Nearby». Открытое окно сохраняет соединение и предлагает выбрать получателя. В Windows 11 пункт доступен в «Показать дополнительные параметры». Папки сначала упакуйте в ZIP; до 100 файлов за раз. Подробнее: [контекстное меню](CONTEXT-MENU.md).
